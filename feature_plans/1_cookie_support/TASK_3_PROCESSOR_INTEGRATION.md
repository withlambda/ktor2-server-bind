### Task 3: Integration into Route Processing

**Description**: Wire the cookie handlers into the route installation and response handling logic.

**TDD Requirement**:
- **Red Phase**: Write an integration test where a controller tries to access a cookie, and verify it fails or receives empty data because the processor doesn't yet populate it.
- **Green Phase**: Update `RouteProcessor` to extract cookies from the request and apply cookies to the response.
- **Refactor Phase**: Ensure the implementation supports all Ktor `Cookie` options (domain, path, secure, etc.) as requested.

**Instructions**:
1.  Edit `src/commonMain/kotlin/com/withlambda/ktor2/server/bind/RouteProcessor.kt`:
    - Update `RouteProcessorBase.customizedResponse` to handle `responseData.responseCookies`.
    - If `responseCookies` is present, iterate over `responseCookies.mapOfCookies` and call `call.response.cookies.append(value)`.
    - This follows the Zero-reflection pattern by relying on the DTO to provide a pre-built map of cookies (which will be generated by KSP in Feature 6).
2.  Update `RouteConfig` to provide `getRequestCookies(call: ApplicationCall)` which returns the appropriate handler.

**Verification**:
- Integration test with a controller that reads a cookie and sets a cookie, verifying the `Set-Cookie` header in the response.
